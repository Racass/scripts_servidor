2Criar no fileserver

O criador de usuários original não está versionado neste repositório. O bloco abaixo é o procedimento manual compatível com o estado atual. Se o script oficial for recuperado, prefira-o e mantenha suas rotinas de backup, rollback, ACL e testparm.

Entre em fileserver.corp como root e defina o username:

NOVO_USUARIO="nome_em_minusculas"

[[ "$NOVO_USUARIO" =~ ^[a-z_][a-z0-9_-]{0,31}$ ]] || exit 1
[[ "$NOVO_USUARIO" != "admin" ]] || exit 1
[[ "$NOVO_USUARIO" != "nextcloud_user" ]] || exit 1
! getent passwd "$NOVO_USUARIO" >/dev/null || exit 1
! pdbedit -L | cut -d: -f1 | grep -Fxq "$NOVO_USUARIO" || exit 1

Crie a identidade Linux bloqueada para senha local:

adduser --disabled-password --gecos "" "$NOVO_USUARIO"
usermod -aG samba-users "$NOVO_USUARIO"

Adicione somente os grupos aprovados:

# Execute apenas as linhas aprovadas:
usermod -aG samba-admin "$NOVO_USUARIO"
usermod -aG samba-laudos "$NOVO_USUARIO"
usermod -aG samba-laudos-mega "$NOVO_USUARIO"
usermod -aG samba-administrativo "$NOVO_USUARIO"

Crie a senha Samba interativamente:

smbpasswd -a "$NOVO_USUARIO"
A senha digitada aqui é a senha Samba. Ela não será enviada ao Nextcloud e não deve aparecer em ticket, terminal compartilhado ou arquivo.

Crie a pasta pessoal e replique o padrão de ACL validado:

PASTA="/srv/files/usuarios/$NOVO_USUARIO"

install -d -o "$NOVO_USUARIO" -g samba-users -m 2770 "$PASTA"
setfacl -b "$PASTA"
setfacl -m \
  "u::rwx,u:${NOVO_USUARIO}:rwx,g::---,g:samba-users:---,g:samba-admin:rwx,m::rwx,o::---" \
  "$PASTA"
setfacl -d -m \
  "u::rwx,g::---,g:samba-admin:rwx,m::rwx,o::---" \
  "$PASTA"

Valide antes de exportar:

id "$NOVO_USUARIO"
pdbedit -Lv "$NOVO_USUARIO" |
  sed -n '/^Unix username:/p;/^Account Flags:/p'
stat -c '%a %U:%G %n' "$PASTA"
getfacl -cp "$PASTA"
testparm -s /etc/samba/fileserver.conf >/dev/null

A saída de getfacl -cp "$PASTA" deve seguir exatamente este padrão auditado em uma pasta válida:

user::rwx
user:NOME_DO_USUARIO:rwx
group::---
group:samba-users:---
group:samba-admin:rwx
mask::rwx
other::---
default:user::rwx
default:group::---
default:group:samba-admin:rwx
default:mask::rwx
default:other::---
Não continue se houver permissão para other, samba-users ou algum usuário inesperado.

3Exportar e criar a réplica Nextcloud

No fileserver:

systemctl start export-nextcloud-state.service
systemctl show export-nextcloud-state.service \
  -p Result -p ExecMainStatus

jq --arg u "$NOVO_USUARIO" '
  {
    present: (.users | index($u) != null),
    groups: [
      .groups
      | to_entries[]
      | select(.value | index($u) != null)
      | .key
    ]
  }
' /var/lib/samba-nextcloud-export/state.json
Pare se present não for true ou se os grupos não forem exatamente os aprovados.

No host Nextcloud:

NOVO_USUARIO="mesmo_nome_usado_no_fileserver"

sync-nextcloud-state --dry-run

jq '{
  generation_id,
  new_users,
  conflicting_users,
  memberships_add,
  memberships_remove,
  counts
}' /var/lib/samba-nextcloud-sync/state/last-plan.json

O plano deve mostrar:

  • o novo username em new_users;
  • zero conflitos;
  • somente memberships aprovados em memberships_add;
  • zero remoções inesperadas.
GENERATION="$(
  jq -r '.generation_id' \
    /var/lib/samba-nextcloud-sync/state/last-plan.json
)"

sync-nextcloud-state \
  --apply-additive \
  --reviewed-generation "$GENERATION"

Confirme a conta desabilitada e marcada:

docker exec -u www-data nextcloud-app \
  php occ user:info "$NOVO_USUARIO"

docker exec -u www-data nextcloud-app php occ user:setting \
  "$NOVO_USUARIO" samba_nextcloud_sync managed_by \
  --default-value=''

docker exec -u www-data nextcloud-app php occ user:setting \
  "$NOVO_USUARIO" samba_nextcloud_sync onboarding_pending \
  --default-value=''

Os comandos user:setting acima apenas consultam os markers; --default-value='' não altera seu conteúdo.

Resultado esperado: conta desabilitada, managed_by=samba-nextcloud-sync e onboarding_pending=1.

4Fazer o onboarding

Defina uma senha Nextcloud independente, interativamente:

docker exec -it -u www-data nextcloud-app \
  php occ user:resetpassword "$NOVO_USUARIO"
Não copie automaticamente a senha Samba. Nunca passe a senha em argumento, variável persistente, arquivo ou log.

Somente depois da senha ser definida:

docker exec -u www-data nextcloud-app php occ user:setting \
  --delete "$NOVO_USUARIO" \
  samba_nextcloud_sync onboarding_pending

docker exec -u www-data nextcloud-app \
  php occ user:enable "$NOVO_USUARIO"

Confirme:

docker exec -u www-data nextcloud-app \
  php occ user:info "$NOVO_USUARIO"

docker exec -u www-data nextcloud-app php occ user:setting \
  "$NOVO_USUARIO" samba_nextcloud_sync onboarding_pending \
  --default-value=''

Resultado esperado: enabled: true e marker de onboarding vazio, preservando managed_by.

!Se algo falhar

Não execute user:delete, não apague a pasta pessoal, não remova journals e não edite o banco Nextcloud para “tentar novamente”.
SintomaAção segura
Usuário ausente no JSON Rever id, tdbsam, grupos e journal do exportador.
Conflito no dry-run Parar. Verificar se já existe conta Nextcloud sem marker. Adoção é procedimento separado e exige snapshots.
Generation mudou Executar novo dry-run e revisar novamente. Nunca reutilizar UUID antigo.
Conta desabilitada após apply Comportamento esperado; concluir onboarding.
Storage não aparece Rever membership, External Storage, CIFS, path e ACL. Não conceder grupos extras como atalho.
Apply parcial Preservar o journal em /var/lib/samba-nextcloud-sync/state/provisioning/ e executar novo dry-run antes de retomar.

Para adoção, lifecycle, rename, purge ou restore, use nextcloud/OPERATIONS.md e tire os snapshots obrigatórios antes de qualquer ação destrutiva.
